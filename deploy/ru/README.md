# Размещение сайта на российском сервере

GitHub Pages используется для просмотра незавершённой версии. Постоянный сайт
клиники планируется разместить на российском хостинге. Этот набор файлов
подготавливает код к переносу, но сам по себе не подтверждает соблюдение 152-ФЗ.

1. Выберите хостинг с площадкой, журналами и резервными копиями в РФ.
   Получите от провайдера условия обработки технических данных и место хранения.
2. Уточните домен и проверьте DNS, HTTPS и полномочия на настройку HTTP-заголовков.
3. Подтвердите у хостинга юридическое наименование провайдера, регион серверов
   и срок хранения технических журналов. Затем соберите сайт в корне домена:

   ```sh
   NEXT_PUBLIC_HOSTING_PROVIDER='Название провайдера' \
   NEXT_PUBLIC_HOSTING_REGION='Московской области' \
   NEXT_PUBLIC_HOSTING_LOG_RETENTION='30 дней' \
   npm run build:ru
   ```

   Значения в примере условные: используйте только подтверждённые данные.
   Команда создаёт `out/` без изменения сборки для демонстрационной ссылки.
4. Скопируйте **содержимое** `out/` на сервер в каталог, закрытый от записи
   веб-процессом. Пример `nginx-site.conf.example` включите в HTTPS server block
   и замените путь `root`. Для Apache/shared hosting настройте аналогичные
   заголовки у провайдера. Проверьте, что заголовки применяются и к ошибкам.
5. Пересмотрите `/privacy`, `/consent` и `/cookies`: данные хостинга подставляются
   при сборке, остальные условия и сроки надо проверить по договорам. Проверку
   текста проводят оба оператора (ООО и ИП) и их юрист до запуска.
6. Проверьте в YCLIENTS, кто указан оператором в форме записи, какая политика
   и согласие там показываются, место хранения/backup данных и договор с
   клиникой. Для двух юрлиц нужен понятный исполнитель каждой записи.
7. Проверьте актуальность уведомлений операторов в Роскомнадзор, доступы
   сотрудников к YCLIENTS, права на фотографии и процессы удаления/инцидентов.
8. Перед переключением домена откройте Network в браузере: до согласия нет
   запросов к Яндексу и другим третьим сторонам; после разрешения карта и
   отзывы работают. Проверьте мобильную версию и путь записи.

На статическом сайте нет собственной формы, базы заявок и админки. Настройки
rate limiting, CSRF и резервного копирования базы здесь неприменимы. HTTPS,
серверные заголовки, журналы и их сроки хранения зависят от конечного хостинга.
